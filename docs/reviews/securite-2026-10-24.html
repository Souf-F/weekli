Les 3 risques principaux :

  1. Le droit à l'effacement est incomplet et la page Confidentialité promet plus que le code : le token GitHub, le nom et l'email restent stockés côté connecteur MCP (grants et Durable Objects) après « Supprimer mes données ».
  2. Les données sont rattachées au login GitHub, qui est renommable et réattribuable : un nouveau titulaire d'un ancien login hériterait des brouillons et des domaines vérifiés de l'ancien.
  3. Une dépendance d'exécution du Worker est vulnérable (zod 4.5.4, GHSA-mrhx-c7xc-m3w5, sévérité haute) et les polices Google Fonts transmettent l'IP des visiteurs à Google sans consentement.

Points forts constatés : PKCE S256 des deux côtés, consentement MCP par client avant GitHub (bibliothèque officielle), cookies __Host- HttpOnly SameSite=Lax, vérification d'Origin sur toutes les écritures, sessions et données chiffrées AES-256-GCM avec HKDF, CSP stricte sans script inline, validation stricte des paramètres GitHub, global_fetch_strictly_public, pas de shell dans les scripts vidéo, historique Git propre, secret scanning et push protection actifs sur GitHub.

3. Détail des problèmes

MAJEUR

MAJEUR M1. apps/server/src/lib/donnees.ts:7 et apps/web/src/pages/Legal/Confidentialite.tsx:89 : effacement incomplet, promesse inexacte

  • Problème : DELETE /api/moi/donnees (routes/api.ts:73) supprime seulement brouillons:<login>, domaines:<login> et la session courante. Restent : les grants et tokens MCP de @cloudflare/workers-oauth-provider (props chiffrées contenant login, nom, email et token GitHub, refresh token valable 30 jours et renouvelé à chaque rafraîchissement), le stockage des Durable Objects WeekliMCP (voir M2), les autres sessions du même compte (autres navigateurs, jusqu'à 8 h), et le token GitHub lui-même, jamais révoqué auprès de GitHub. Or la page Confidentialité affirme : « Tout ce que Weekli détient sur toi est supprimé immédiatement : session, token GitHub, brouillons, domaines et style d'écriture ».
  • Preuve : lecture de donnees.ts (deux delete KV seulement) ; node_modules/@cloudflare/workers-oauth-provider/dist/oauth-provider.js:5084 (DEFAULT_REFRESH_TOKEN_TTL = 720 * 60 * 60) ; le handoff backend le reconnaît (point 2).
  • Scénario : un utilisateur exerce son droit à l'effacement depuis le site, croit être effacé, mais son connecteur Claude continue de fonctionner et Weekli conserve son token GitHub et son email. Non-conformité à l'article 17 et information trompeuse (article 12).
  • Correction : stocker userId (id GitHub numérique) dans la session ; dans effacerDonnees, appeler env.OAUTH_PROVIDER.listUserGrants(userId) puis revokeGrant pour chacun, purger les Durable Objects de l'utilisateur (voir M2), supprimer toutes les sessions du compte (index sessions:<userId> ou valeur versionnée), révoquer le token GitHub (DELETE https://api.github.com/applications/{client_id}/grant avec authentification basique client_id et secret). Tant que ce n'est pas fait, corriger le texte de la page Confidentialité et du panneau PanneauDonnees.tsx.
  • Agent concerné : backend-senior (code), frontend-senior (textes).

MAJEUR M2. apps/server/src/mcp/agent.ts:30 (via agents McpAgent.updateProps) : token GitHub en clair et sans durée de conservation dans les Durable Objects

  • Problème : la bibliothèque agents@0.30.0 enregistre les props de chaque session MCP dans le stockage du Durable Object (ctx.storage.put("props", props), node_modules/agents/dist/mcp/index.js:1442). Ces props contiennent login, name, email et accessToken (token GitHub) en clair. Un Durable Object est créé par session MCP, et rien dans Weekli n'appelle destroy() ni storage.deleteAll() : les données s'accumulent sans limite de durée. Cela contredit docs/securite.md (« tokens chiffrés », « Fuite du stockage » protégée) et la durée de 90 jours annoncée.
  • Preuve : lecture du code de la bibliothèque (lignes 1440 à 1452) ; aucune occurrence de destroy ou deleteAll dans apps/server/src.
  • Scénario : une fuite ou un accès indu au stockage Durable Object expose directement des tokens GitHub (portée read:user, impact limité mais réel) et des emails ; en RGPD, conservation illimitée sans base (article 5.1.e).
  • Correction : ne pas mettre le token GitHub dans les props transmises au DO, ou le chiffrer avec chiffrer() avant (et le déchiffrer dans le getter octokit) ; retirer email (m1) ; programmer une alarme dans le DO (this.schedule ou ctx.storage.setAlarm) qui appelle this.destroy() après inactivité (par exemple 24 h ou 90 jours au maximum) ; prévoir la purge dans M1. Fixer explicitement refreshTokenTTL dans OAuthProvider (par exemple 30 jours non renouvelés) et le documenter.
  • Agent concerné : backend-senior.

MAJEUR M3. apps/server/src/lib/brouillons.ts:7, apps/server/src/lib/domaines.ts:11 et :34 : données rattachées au login GitHub au lieu de l'id numérique

  • Problème : les clés KV (brouillons:<login>, domaines:<login>), le jeton HMAC de vérification de domaine, la limitation de débit et le login des outils MCP reposent sur le nom d'utilisateur GitHub. Un login GitHub peut être renommé, et l'ancien nom devient libre et réutilisable par n'importe qui. La session (types.ts:12) ne garde même pas l'id numérique.
  • Preuve : lecture du code ; la bibliothèque OAuth, elle, indexe bien par userId: String(user.id) (oauth-mcp.ts:94), ce qui montre l'incohérence.
  • Scénario : Alice (login alice) renomme son compte. Mallory crée un compte alice, se connecte à Weekli : il lit les brouillons d'Alice (contenu non publié) pendant leur durée de conservation, et hérite de ses domaines vérifiés, donc peut lancer des captures de son site au nom de Weekli. Le jeton de vérification étant dérivé du login, il est aussi identique.
  • Correction : utiliser user.id (numérique, immuable) dans la session, les props MCP, les clés KV, le jeton HMAC et la clé de limitation de débit ; migrer les clés existantes au premier login (lire login, réécrire sous id, supprimer l'ancienne).
  • Agent concerné : backend-senior (architecte pour la migration).

MAJEUR M4. apps/web/index.html:9 à 14 et apps/web/public/_headers:4 : Google Fonts chargées sans consentement

  • Problème : chaque page charge fonts.googleapis.com et fonts.gstatic.com dès l'affichage, ce qui transmet l'adresse IP de tout visiteur à Google (transfert hors UE) sans consentement ni nécessité technique. La page Confidentialité le mentionne (ligne 72) mais l'information ne remplace pas une base légale. Jurisprudence connue : LG München, 20 janvier 2022 (3 O 17493/20) ; la CNIL recommande l'hébergement local des polices.
  • Preuve : index.html lignes 9 à 14 ; CSP qui autorise ces deux domaines ; bundle compilé : https://fonts.googleapis.com présent dans index.html produit.
  • Scénario : plainte d'un visiteur ; la requête part avant tout choix, et aucun bandeau ne permet de la refuser.
  • Correction : héberger les polices (Instrument Serif, Geist, JetBrains Mono, toutes sous licence OFL) dans apps/web/public/fonts/ avec @font-face, retirer les <link> Google et les deux domaines de la CSP (style-src 'self'; font-src 'self'), puis retirer la phrase de la page Confidentialité.
  • Agent concerné : frontend-senior.

MAJEUR M5. apps/web/src/pages/Legal/Confidentialite.tsx : information des personnes incomplète et en partie inexacte (articles 13 et 14)

  • Problème :
  • aucune base légale indiquée pour chaque traitement (contrat ou intérêt légitime pour le service, intérêt légitime pour la limitation de débit) ;
  • destinataires et sous-traitants incomplets : GitHub (identification, lecture des données), Anthropic (mode site, appelé depuis le navigateur), Cloudflare Browser Run (captures), Cloudflare Workers Logs (journaux avec erreurs, observability.enabled: true dans wrangler.jsonc:37) ; seul Cloudflare est cité ;
  • transferts hors UE (Cloudflare, GitHub, Anthropic, Google : États-Unis) sans mention du mécanisme (Data Privacy Framework ou clauses contractuelles types) ;
  • l'email GitHub collecté par le connecteur MCP (oauth-mcp.ts:100) n'est pas listé ; le connecteur MCP lui-même n'est pas décrit (grants, durée 30 jours) ;
  • inexactitudes : ligne 46, « le style d'écriture [est] chiffré dans Cloudflare KV » alors qu'il n'est stocké que dans le navigateur (lib/reglages.ts:47) ; ligne 61, « renouvelé à chaque utilisation » alors que le TTL n'est renouvelé qu'à chaque écriture ; les entrées KV écrites avant 9935891 n'ont aucun TTL ;
  • droit d'accès et de portabilité : pas d'export (seul l'affichage dans l'app) ; contact uniquement par discussion publique GitHub.
  • Preuve : lecture de la page à d40f24a ; le handoff frontend signale lui-même les points 1 et 2.
  • Scénario : information non conforme, donc traitement contestable en cas de contrôle ou de réclamation CNIL.
  • Correction : ajouter un tableau finalité, données, base légale, durée, destinataires ; lister les sous-traitants et leur localisation ; corriger les deux inexactitudes ; ajouter un moyen de contact privé (adresse dédiée ou formulaire) ; prévoir un GET /api/moi/donnees d'export JSON (brouillons, domaines, profil). Faire relire par un juriste.
  • Agent concerné : architecte (contenu), frontend-senior (page), backend-senior (export).

MAJEUR M6. package-lock.json : zod 4.5.4 vulnérable dans le runtime du Worker, 13 vulnérabilités npm

  • Problème : zod@4.5.4 (dépendance directe de @weekli/server, de agents et du SDK MCP) est affecté par GHSA-mrhx-c7xc-m3w5 (sévérité haute, CVSS 8.2) : épuisement mémoire en validant un très grand tableau. Le Worker valide avec zod les entrées des outils MCP et les messages JSON-RPC envoyés par tout utilisateur authentifié (n'importe quel compte GitHub). npm audit : 13 vulnérabilités (2 modérées, 11 hautes) ; la CI (npm audit --audit-level=moderate) échouera au prochain push.
  • Preuve : npm audit, osv-scanner (4 vulnérabilités dans 2 paquets : zod, undici) ; npm ls zod.
  • Scénario : un client MCP authentifié envoie à sauver_brouillons un tableau de plusieurs millions d'éléments invalides ; l'isolat du Durable Object sature sa mémoire. L'exploitabilité exacte dans le runtime Workers n'a pas été testée (NON VÉRIFIÉ dynamiquement).
  • Correction : passer à zod@>=4.6.6 (et overrides dans le package.json racine si une dépendance l'épingle), mettre à jour wrangler (undici 7.30.1, dev seulement) ; pour @remotion/* (outil local uniquement), suivre le correctif amont. Relancer npm audit.
  • Agent concerné : backend-senior.

MINEUR

MINEUR m1. apps/server/src/routes/oauth-mcp.ts:100 et types.ts:7 : email collecté sans usage

L'email GitHub est mis dans les props MCP mais n'est utilisé nulle part (minimisation, article 5.1.c). Correction : retirer email des Props. Agent : backend-senior.

MINEUR m2. apps/server/src/routes/auth.ts:68 : token GitHub non révoqué à la déconnexion

/auth/logout supprime la session KV mais le token reste valide chez GitHub. Si l'app OAuth ne fait pas expirer ses tokens (NON VÉRIFIÉ : docs/installation.md:19 parle de l'option « Expire user access tokens », que je n'ai pu confirmer pour une OAuth App), il reste valable indéfiniment. Si les tokens expirent bien en 8 h, le refresh_token renvoyé par GitHub est ignoré (github-oauth.ts:55) et le connecteur MCP (refresh 30 jours) cessera de fonctionner après 8 h. Correction : vérifier le réglage réel de l'app, révoquer à la déconnexion, et traiter le refresh GitHub ou aligner les durées. Agent : backend-senior.

MINEUR m3. apps/server/src/lib/capture.ts:44 à 68 : contournement de la preuve de propriété et SSRF résiduelle du navigateur

Seule l'URL de la page principale est contrôlée. Une page d'un domaine vérifié peut afficher en <iframe> n'importe quel site public (ou toute adresse joignable par le navigateur Browser Run) ; l'image renvoyée le montre. Elle peut aussi déclencher une navigation juste après le contrôle de location.href (fenêtre de 200 ms avant la capture). Correction : activer Fetch.enable en CDP et refuser toute requête de type Document (cadres compris) hors domaines vérifiés ; désactiver JavaScript (Emulation.setScriptExecutionDisabled) après le floutage ; recontrôler l'URL après Page.captureScreenshot. L'accès réseau interne du navigateur Browser Run relève de Cloudflare : NON VÉRIFIÉ. Agent : backend-senior.

MINEUR m4. apps/server/src/lib/flou.ts : floutage partiel

Ne couvre que les nœuds texte de document.body : valeurs des input type=text et textarea, shadow DOM, iframes, images et canvas, IPv6, numéros de téléphone, noms ne sont pas floutés ; un flou de 6 px sur du texte court peut parfois être inversé. Correction : flouter aussi input, textarea, [contenteditable], parcourir les shadowRoot, monter le flou ou remplacer par un pavé opaque, documenter la limite. Agent : backend-senior.

MINEUR m5. apps/server/src/lib/domaines.ts:80 : domaines jamais revérifiés

Un domaine vérifié le reste jusqu'à 90 jours sans activité, même si son propriétaire change. Correction : revérifier avant chaque capture si la preuve date de plus de 7 jours. Agent : backend-senior.

MINEUR m6. apps/server/src/mcp/agent.ts:38 : login figé à l'initialisation du Durable Object

Les outils utilisent le login capturé dans init() tandis que this.octokit lit les props courantes. Le Durable Object est nommé d'après l'en-tête mcp-session-id fourni par le client (agents/dist/mcp/index.js:107 et :176), sans vérification qu'il appartient au même utilisateur. Si un identifiant de session fuitait, un autre utilisateur authentifié lirait les brouillons du premier. Exploitation non testée et peu probable (identifiant aléatoire de 256 bits). Correction : lire this.props.login à chaque appel d'outil et refuser si l'utilisateur des props diffère de celui enregistré dans le DO. Agent : backend-senior.

MINEUR m7. packages/core/src/github.ts:72 et :101, .claude/skills/video-projet/SKILL.md : injection de prompt

README, messages et extraits de diff sont renvoyés bruts à Claude, sans balisage indiquant un contenu non fiable, et les diffs peuvent contenir des secrets commités par l'utilisateur. Un commit tiers fusionné en squash dans un repo de l'utilisateur lui est attribué. Le skill video-projet se déclare utilisable « sur n'importe quel dépôt » et fait lire README et docs à Claude Code, qui dispose d'un shell. Impact réduit côté Weekli (outils sans effet de bord hors brouillons et captures de domaines vérifiés). Correction : envelopper les contenus de repo dans un champ contenu_non_fiable et le rappeler dans la description des outils, masquer les motifs de secrets (ceux de flou.ts) dans les extraits de diff, avertir dans le skill de ne l'utiliser que sur des dépôts de confiance. Agent : backend-senior, architecte pour le skill.

MINEUR m8. apps/video/scripts/capturer.mjs:17 et :25, produire.mjs:26 et :53 : arguments non validés dans le pipeline vidéo local

execFileSync sans shell : pas d'injection de commande. Mais projet et nom ne sont pas validés (../ permet d'écrire hors du dossier prévu), et le texte de voix est passé à say sans -- (un texte commençant par - serait lu comme option). capturer.mjs ouvre n'importe quelle URL, y compris locale. Outil interne, lancé par l'opérateur. Correction : valider projet et nom avec /^[a-z0-9-]{1,40}$/, ajouter "--" avant le texte de say. Agent : backend-senior.

MINEUR m9. apps/server/src/lib/chiffrement.ts:19 et github-oauth.ts:10 : String.fromCharCode(...octets) plante au-delà d'environ 125 Ko

Preuve : node -e avec un Uint8Array de 125 000 octets : RangeError: Maximum call stack size exceeded (même moteur V8 que Workers). Un historique de 100 brouillons de 6 000 caractères (environ 600 Ko) ne peut plus être enregistré : déni de service sur son propre compte, erreur 502. Correction : encoder en base64 par blocs (boucle de 32 Ko) ou via Uint8Array.prototype.toBase64 si disponible. Agent : backend-senior.

MINEUR m10. apps/web/src/lib/reglages.ts:50 : clé API Anthropic lisible par JavaScript

Choix de conception documenté et accepté (mode bonus). La protection repose entièrement sur la CSP et sur l'intégrité des dépendances du bundle ; connect-src https://api.anthropic.com reste un canal d'exfiltration possible si un script étranger s'exécutait (requête faite avec la clé de l'attaquant contenant celle de la victime). Correction : garder sessionStorage par défaut (déjà le cas), afficher un avertissement sur l'option « mémoriser », recommander une clé dédiée avec plafond de dépense. Agent : frontend-senior.

MINEUR m11. apps/web/public/_headers et apps/server/src/lib/pages.ts:20 : en-têtes à compléter

Pas de Strict-Transport-Security sur les fichiers du front (le Worker ne l'ajoute que sur ses propres réponses), pas de Cross-Origin-Opener-Policy: same-origin ; la page de consentement autorise style-src 'unsafe-inline' (sans risque pratique, tout est échappé). Correction : ajouter HSTS et COOP dans _headers, passer le style de la page de consentement en nonce ou en hash. Agent : frontend-senior, backend-senior.

MINEUR m12. Dépôt GitHub et outillage

Branche main non protégée (gh api .../branches/main/protection : 404) ; alertes Dependabot et mises à jour de sécurité désactivées ; signalement privé de vulnérabilité désactivé alors que SECURITY.md demande de l'utiliser ; actions de CI référencées par tag et non par SHA ; aucun hook local installé dans .git/hooks alors que docs/securite.md et SECURITY.md l'affirment ; exclusions Git uniquement dans .git/info/exclude (aucun .gitignore partagé, choix assumé du propriétaire) ; .dockerignore n'exclut pas .env* ; images Docker de dev exécutées en root ; dependabot.yml sans délai de refroidissement. Correction : activer protection de branche, Dependabot alerts et security updates, private vulnerability reporting ; installer le hook (git config core.hooksPath vers un dossier versionné) ; ajouter **/.env* à .dockerignore. Agent : architecte.

MINEUR m13. Historique Git public : email personnel de l'auteur visible

Tous les commits portent l'adresse personnelle (sfec****), alors que les mentions légales indiquent « aucun email publié ». Correction : utiliser l'adresse noreply GitHub pour les prochains commits et activer « Block command line pushes that expose my email ». Sans réécriture de l'historique (contrainte du brief). Agent : architecte.

MINEUR m14. apps/server/src/lib/chiffrement.ts et domaines.ts:24 : gestion de la clé racine

Une seule clé COOKIE_ENCRYPTION_KEY sert au chiffrement AES (HKDF, correct), au HMAC des domaines (dérivation ad hoc secret:domaines) et au consentement mémorisé ; pas de contrôle de longueur au démarrage, pas de version de clé pour une rotation, pas de données associées (AAD) liant un chiffré à sa clé KV. Correction : dériver aussi la clé HMAC par HKDF, refuser de démarrer si la clé fait moins de 32 octets, préfixer les chiffrés par une version, passer la clé KV en additionalData. Agent : backend-senior.

MINEUR m15. Mineurs

Rien n'indique l'âge minimal (GitHub impose 13 ans ; la majorité numérique est de 15 ans en France). Correction : une phrase dans la page Confidentialité. Agent : frontend-senior.

MINEUR m16. apps/server/wrangler.jsonc:26 et :36 : configuration de déploiement à finaliser

PUBLIC_URL vaut http://localhost:8788 et l'id KV est un placeholder. Déployé tel quel, l'audience des tokens MCP serait fausse. Correction : à mettre dans la checklist de déploiement. Agent : architecte.

MINEUR m17. Dépendances de développement vulnérables

undici (via wrangler, dev), @remotion/* (via zod, outil vidéo local) : sans exposition en production. Correction : mises à jour avec M6. Agent : backend-senior.
